# Comic Cascade — architecture overview

**Purpose of this file.** A map of how the project works and *why it is shaped
this way*, written to inform code review (human or LLM). It complements the
other docs rather than repeating them — [README](README.md) is the user-facing
tour, [CONFIG.md](CONFIG.md) the configuration reference,
[SECURITY.md](SECURITY.md) the threat model and reporting channel,
[CHANGELOG.md](CHANGELOG.md) the history. When a code change alters anything
described here, update this file **in the same commit**.

## 1. What this is

**Status: v0.3.0.** A minimal, self-hostable comic reader (0BSD): browse
folders of CBZ/CBR/PDF files, read them in the browser, resume where you left
off. The guiding constraint throughout is **a fast reader, not a platform** —
no accounts, no metadata scraping, no collections, no server-side rendering of
UI. Features that would grow it into a platform are non-goals (§13).

## 2. Core principle

**The server is a read-only, path-confined file server with an extract-once
cache; the browser owns all reading UX; identity is the reverse proxy's
problem.** The app never writes into a library, never authenticates anyone,
and holds no sessions — every request stands alone, carrying whatever identity
the deployer's proxy asserts in headers. The only writable location is the
cache directory.

## 3. Architecture map

Backend (FastAPI, `app/`):

| Module | Owns |
|---|---|
| `main.py` | routes; the read-only API surface; static mount (last, so `/api/*` wins); the `no-cache`+`nosniff` middleware |
| `config.py` | env/TOML config resolution (§10); frozen `Config`/`Library` dataclasses |
| `libraries.py` | the runtime library registry: immutable when config-derived, mutable + persisted to `<cache>/libraries.json` when a browse root enables UI management |
| `paths.py` | `safe_resolve` — every filesystem access goes through it (§4) |
| `archives.py` | format sniffing, ZIP/RAR/7z extraction, PDF rendering, and all the hardening around them (§5) |
| `cache.py` | the extract-once disk cache with LRU eviction (§5) |
| `auth.py` | optional proxy-delegated identity + management gating (§6) |
| `progress.py` | the server tier of read-resume: SQLite `progress.db` (§7) |
| `util.py` | comic/image classification, natural sort |

Frontend (no build step, vanilla ES modules, `web/js/`):

| Module | Owns |
|---|---|
| `main.js` | bootstrap + hash router (browse view ↔ reader view) |
| `api.js` | fetch wrappers |
| `browser/` | library picker, file tree, "continue reading" row, manage modal |
| `reader/reader.js` | the virtualized reader (§8) |
| `reader/layout.js` | pure layout math (node-testable) |
| `reader/zoom-math.js` | pure zoom/pan transform math (node-tested): focal-preserving zoom, pan clamps, scale caps |
| `reader/gestures.js` | unified pinch/pan/double-tap input stream (pure node-tested pointer reducer + DOM adapter); carries the device-verified 2-finger `preventDefault` hatch — `touch-action` alone does NOT stop Android Chrome from cancelling and keeping a pinch |
| `reader/zoom.js` | the SCROLL↔ZOOM state machine + zoom overlay (§8) |
| `reader/settings.js` | per-device reader prefs in `localStorage` |
| `progress.js` | both read-resume tiers + the merge (§7); pure helpers are node-testable |
| `theme.js` | light/dark theme |

## 4. Filesystem & confinement model

Libraries resolve from config in a fixed order (TOML `[[library]]` tables →
`$CASCADE_LIBRARY` → auto-scan of a libraries dir → a single `/library`
mount — see CONFIG.md). With a **browse root** configured, the library set
becomes UI-manageable (add/remove/reorder, a directory picker) and persists to
`<cache>/libraries.json`, seeded once from static config.

Two confinement boundaries, same pattern (`resolve()` then
`is_relative_to(root)`, leading slashes stripped so absolute-looking input
can't jump to `/`):

- `paths.safe_resolve(library, rel)` confines every read to that library's
  root. Escapes and unknown libraries both return **404, never 403** — the API
  must not act as an oracle for what exists outside a library.
- `libraries._confine` bounds management: a library may point at the browse
  root or below it, nothing else. `/api/fs` (the picker) lists directories
  only within it.

The app opens library files strictly read-only; there is no code path that
writes into a library.

## 5. Archive/PDF pipeline & cache

**Dispatch is by content sniff, not extension** — real-world `.cbz` files are
sometimes 7-Zip or RAR containers (a mislabeled "zip" that fails to open falls
through to `unar`). ZIP extracts in-process via `zipfile`; RAR/7z/unknown go
through `unar`; PDF renders via `pypdfium2` at 144 DPI.

Hardening (see SECURITY.md for the threat model):

- **Zip-Slip is structurally impossible**: output filenames are generated by
  index (`00000.jpg`…); archive-internal names are never used as paths.
- **Decompression bombs**: ZIP checks declared uncompressed sizes up front,
  then enforces the same cap during the copy (headers can lie). `unar` runs
  under an `RLIMIT_FSIZE` cap, a timeout (also covers password prompts), `--`
  end-of-options (a path can never parse as a flag), and a post-extraction
  tree-size check. PDFs have a page cap.
- **Symlink smuggling**: only regular files that physically resolve inside the
  extraction dir are collected — an archive containing `page.jpg -> /etc/passwd`
  serves nothing.
- Errors surface as a sanitized 422 (“could not open this comic”); internal
  paths never reach a response. `/api/healthz` reports readiness booleans only.

**Cache** (`<cache>/archives/<hash>/` + `meta/<hash>.json` + `index.db`): a
comic is extracted once; the key hashes `library + relpath + mtime + size`, so
a replaced file gets a fresh entry and the stale one ages out. Eviction is
LRU over **whole archives** against a byte budget (to 80% when exceeded), plus
a minimum-free-space floor on the cache volume. Concurrency: one asyncio lock
per archive hash (concurrent openers await a single extraction; the lock map is
a `WeakValueDictionary` so it can't grow unbounded), a global semaphore bounds
simultaneous extractions, and the blocking work runs in a worker thread.
In-flight hashes are protected from eviction.

## 6. Identity & authorization

The app **never authenticates**. If `CASCADE_USER_HEADER` is configured, the
current user is read per request from that header, which the deployer's
forward-auth proxy (Authentik, Authelia, oauth2-proxy, …) is expected to set.
Group values split on `|` **or** `,` so the major proxies work without extra
config. **The trust prerequisite is the proxy stripping client-supplied copies
of these headers** — the app cannot verify that; a deployment that skips it
has no security. With nothing configured, the app is anonymous and global.

Authorization gates exactly one thing: **library management** (add / remove /
reorder / the `/api/fs` picker → 403). Reading and browsing are never gated —
access control for reading is the proxy's job (§12). Management requires a
browse root, and then: with `CASCADE_ADMINS` / `CASCADE_ADMIN_GROUPS`
configured, the request must match one of them (an unidentified request
matches nothing — fail closed); with **no allowlist configured, management is
open to anyone who reaches the app** — deliberate, so a single-user deployment
needs zero config, but a shared deployment should set an allowlist.

## 7. Read-resume (progress)

Two tiers, one interface, merged **freshest-`updated_at`-wins**:

- **`localStorage` (always on)** — per-device resume for everyone, including
  anonymous deployments. Newest ~50 records kept.
- **Server tier (only when the proxy asserts identity)** — rows in
  `<cache>/progress.db`, keyed `(user, library, path)`. The user key is
  **always derived server-side from trusted headers, never accepted as a
  request parameter** — that is the IDOR guard. Keys prefer a stable uid
  header over the username (renames don't orphan progress) and are
  tier-prefixed (`uid:`/`user:`) so a username can never collide with another
  user's uid. Consequence: enabling `CASCADE_UID_HEADER` later re-keys
  existing progress (documented in CONFIG.md).

Semantics a reviewer should not "fix":

- **Forgetting is a page-0 tombstone POST, not a DELETE.** A deleted row is
  invisible to the freshest-wins merge, so another device's stale local copy
  would resurrect the chip; a tombstone competes in the merge and shadows it
  everywhere. Page-0 rows are hidden from every surface, and tombstone POSTs
  ride the same mutation chain as position writes (no reordering race) and
  are `sendBeacon`-able on unload. The DELETE endpoint exists for true
  removal but the app never calls it.
- **`/api/progress/recent` hides rather than prunes on doubt.** A row is
  pruned only when its library root is reachable *and* the comic is gone; a
  missing library or any filesystem error hides the row but keeps it — a
  transient mount hiccup must never destroy a reading position. The scan runs
  past hidden rows so they can't starve the visible ones.
- **Progress keys are canonicalized** through the same resolver as reads, so
  alias spellings (`./a.cbz`, `x/../a.cbz`) collapse into one row — a user
  can't grow the store with variants of one file. Inputs are length- and
  range-capped.
- **Browser-local records are partitioned per user** by an opaque scope token
  (a short hash the server derives from the identity — nothing about the user
  lives in storage keys), so accounts sharing one browser profile don't see
  each other's chips. No identity → the shared per-device bucket, exactly as
  before.

## 8. Reader frontend

Two scroll modes — vertical fit-width and horizontal fit-height with LTR/RTL —
**virtualized**: only pages near the viewport are in the DOM (an overscan
window plus a small preload-ahead). Pages are **never upscaled** past native
resolution. Navigation is authoritative: `goTo()`/`relayout()` set the page
directly and briefly lock scroll-driven detection so the programmatic scroll's
own events can't re-pick a neighbouring page; free-scroll detection is
centre-line based and edge-aware (the browser clamps scroll positions at the
extremes, so an edge page could otherwise never be "current"). Reader state
(mode, RTL, gap, page) lives in the URL for deep-linking and refresh-resume;
device prefs persist in `localStorage`. Fullscreen handles the WebKit-prefixed
API and hides the button on iPhone Safari where the API doesn't exist.
**Zoom** is an overlay BESIDE the reader, never a transform on it
(`reader/zoom.js`): entering creates a `.zoom-layer` inside the reader root
(the fullscreen element) holding one fresh `<img>` of the page UNDER the
gesture point (hit-tested against the mounted pages — at a page seam the
viewport-center "current" page is routinely the tapped page's neighbour; same
immutable-cached URL), covering the page's on-screen rect; the scroller is
frozen with `overflow: hidden` (scroll position preserved), so the
virtualizer, layout and page detection never know zoom exists and exiting
resumes SCROLL at the same page by construction. Enter: pinch-out past the
threshold, double-tap/double-click (preset), or `+`. In ZOOM: pinch or
ctrl-wheel scales about the focal point, drag / plain wheel pans (clamped
with a TAPERED slack margin — a covered axis may overshoot flush by up to a
quarter viewport so edge panels can be pulled toward the middle, with the
slack shrinking to zero as the scaled size approaches the viewport so a
zoom-out across the covered/centered crossing cannot teleport the page; a
smaller axis stays centered), `+`/`-` step. An in-flight programmatic smooth
scroll is settled instantly before the overlay measures geometry; a dying
exit-animation overlay is `pointer-events: none` (events fall through to the
scroller immediately) and a stale exit never un-freezes the scroller under a
re-entered session. Exit:
pinch back to fit ("clicks back in"), double-tap, Escape/`0`, any
navigation, or any relayout (resize/rotation/mode/pin change — v1 exits
rather than re-anchoring). Input unification lives in `reader/gestures.js`;
the geometry is `reader/zoom-math.js`; a pinch that starts on the scroller
streams through the SCROLL→ZOOM transition seamlessly (touch pointers are
implicitly captured by the element that saw pointerdown).

Page responses are immutable-cacheable (`max-age=31536000, immutable` + an
`ETag` keyed on the cache hash, which already changes when the source file
does). Everything non-`/api/` is `no-cache` (revalidate, not no-store) so a
deploy shows up on a normal reload. All responses carry `nosniff`.

## 9. HTTP API surface

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/libraries` | open | library list + management/progress capability flags + progress scope token |
| POST / DELETE / PUT | `/api/libraries`, `/api/libraries/{id}`, `/api/libraries/order` | manage | add / remove / reorder libraries |
| GET | `/api/fs?path=` | manage | directory picker, confined to the browse root |
| GET | `/api/tree?library=&path=` | open | one directory's children (never recurses); folders-then-files, natural-sorted; dotfiles always hidden |
| GET | `/api/comic?library=&path=` | open | page count + per-page dimensions; triggers extract-once |
| GET | `/api/page?library=&path=&index=` | open | one page image (immutable-cached) |
| GET / POST / DELETE | `/api/progress` | identity* | this user's position for one comic (no-op without identity) |
| GET | `/api/progress/recent` | identity* | "continue reading" items + tombstones |
| GET | `/api/healthz` | open | readiness booleans; deliberately path-free |

\* "identity" = a no-op / empty response unless the proxy asserts a user; never
an error, so unconfigured deployments behave as if the feature doesn't exist.

## 10. Configuration philosophy

The reference table lives in [CONFIG.md](CONFIG.md) — it is not duplicated
here (two copies of a table always drift). The principles: **everything
optional is off by default** and its absence reproduces pre-feature behavior
exactly; identity/gating **fails closed** once configured; libraries resolve
from the first matching source in a fixed order; the cache directory is the
single writable location and every tunable guards a resource (cache budget,
extraction concurrency, per-archive byte cap, PDF page cap).

## 11. Testing

Python (`pytest`, `tests/`): API surface + confinement (`test_api.py`),
extraction + bomb/symlink guards (`test_archives.py`), management gating
(`test_auth.py`), config resolution (`test_config.py`), both progress tiers'
server half — keys, tombstones, hide-vs-prune (`test_progress.py`), the
library store (`test_store.py`), natural sort (`test_util.py`). Real `unar`
runs in CI; there is no mocked-subprocess layer to drift.

JS (`node --test tests/js/`): the pure layout math, the progress
merge/partitioning helpers, the zoom transform math (focal-point invariant,
pan clamps, scale caps), and the gesture pointer reducer (pinch lifecycle,
pointercancel-means-the-browser-took-it, ghost-pairing) — the modules are
written so their logic imports into Node without a DOM.

CI (GitHub Actions): pytest, `pip-audit` over runtime deps, `node --check`
over every ES module, the JS tests, and a Docker image build.

## 12. Invariants & gotchas (read before reviewing)

- **Open reading is by design.** There is no read auth to "add"; deployments
  wanting private reading put the whole app behind their proxy's gate.
- **404, never 403, for path escapes and unknown libraries** — an existence
  oracle is the vulnerability; don't "correct" the status code.
- **The progress user is never a request parameter.** Adding one (e.g. "admin
  views a user's progress") would delete the IDOR guarantee.
- **Tombstones are POSTs, not DELETEs** (§7). Replacing them with DELETE
  reintroduces the resurrection bug cross-device.
- **Management with a browse root and no allowlist is open** — a documented
  single-user convenience, not a missing check (§6).
- **Never-upscale is a LAYOUT rule**: layout never upscales a page; the
  explicit zoom overlay may (up to `max(3×, native 1:1)`). Don't "unify" them.
- **The reading view sets `maximum-scale=1, user-scalable=no`** (swapped in on
  reader build, restored on teardown) and it is load-bearing, not an a11y
  oversight: during a scroll/fling Chrome delivers NON-cancelable touchmoves,
  so the 2-finger preventDefault hatch cannot fire and a mid-fling pinch would
  fall through to the browser's viewport zoom (zooming the whole app). The
  reader has its own zoom; iOS ignores the attribute (keeping its a11y zoom);
  the browse view keeps normal page zoom. Known environment override: Chrome's
  Accessibility → "Force enable zoom" makes the browser ignore this lock (and
  every site's) — a mid-fling pinch can then still viewport-zoom. That is the
  user's explicit choice; the reader tolerates it (the zoom overlay refuses to
  open while `visualViewport.scale` ≠ 1, so geometry never corrupts) and the
  browser zoom is pinch-out recoverable. Diagnosed the hard way on a real
  device — check that setting FIRST when "pinch zooms the whole app".
- **The cache directory is not disposable.** Besides re-creatable extractions
  it holds `progress.db` (user state) and `libraries.json` (the managed
  library set). Deleting it loses both.
- **Extraction output names are index-generated** — code that starts trusting
  archive-internal names reopens Zip-Slip.
- **Content sniff over extension** in the pipeline: honoring the extension
  breaks real-world mislabeled `.cbz` files.
- **Compose override files append sequences.** If you deploy with a
  `docker-compose.override.yml` and replace a sequence (e.g. `ports`), mark it
  `!override` — otherwise Compose *merges* and the base's binding survives
  alongside yours. With no auth of its own, an accidentally-public port
  bypasses your proxy entirely.
- **Enabling `CASCADE_UID_HEADER` on an existing deployment re-keys progress**
  (tier-prefixed keys, §7) — expected, one-time, documented.

## 13. Non-goals & future direction

Non-goals — these keep "minimal" honest, and PRs adding them will likely be
declined:

- **In-app accounts or login.** Identity stays proxy-delegated, permanently.
- **Per-user library scoping** (different users seeing different collections).
  That's multi-tenancy — a different product.
- **Server-synced client settings.** Theme/scroll-mode/gap are device
  preferences; `localStorage` is their home.
- **Metadata/platform features** (scrapers, collections, ratings, history
  shelves, per-row progress bars).

Pinch-zoom (the long-standing gap — the Fullscreen API disables native page
zoom) is now implemented as the zoom overlay (§8). iOS is untested for lack
of hardware: modern iOS Safari delivers the same pointer events the
Android-verified path consumes, and a defensive `gesture*` shim stops
Safari's own page zoom — reports welcome.
